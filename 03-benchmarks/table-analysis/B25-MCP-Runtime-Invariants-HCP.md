# B25 MCP 风格运行时安全不变量（HCP）— 数据表格与分析

> 论文：From Tool Connection to Execution Control: Benchmarking Security Invariants in MCP-Style Agent Runtimes  
> 表格：[analysis/tables](../B25-mcp-runtime-invariants-hcp/analysis/tables/)  
> 数据集状态：**无公开测试集**（作者仅发布 HCP 运行时代码），以下为论文数据。

## 1. 这个基准测什么

它不是测模型，而是测**执行层控制机制**：在 MCP 式工具运行时里，连接层控制（身份、协议版本、头一致性等）与执行授权层控制（授权匹配、资源规范化绑定、句柄归属与生命周期、数据管道类别、一次性审批）分别能挡住哪些攻击。18 个脚本化攻击 + 25 个合法工作流，另有 AgentDojo 原生任务和真实 MCP 服务实验。

## 2. 主结果（Table 2）

| 模式 | 攻击成功 | 阻止 | 合法任务完成 |
| --- | --- | --- | --- |
| B0 直接执行 | 18/18 | 0 | 25/25 |
| B1 连接层控制 | 11/18 | 7 | 24/25 |
| B1 + 一律拒绝审批 | 3/18 | 14 | **14/25** |
| B2 HCP 运行时 | **0/18** | 18 | 25/25 |
| B3 网关 ACL（同样不变量） | **0/18** | 18 | 25/25 |

- 只做连接层检查挡不住大多数攻击（11/18 成功）；靠“一律拒绝审批”能挡更多，但合法任务完成率掉到 56%。
- 只要在执行层强制同一组不变量（I1–I8），集中式运行时（HCP）和网关 ACL 效果完全一样——关键是不变量本身，不是架构形态。

## 3. 哪个检查最关键（Table 4，逐个移除检查并真实执行）

移除授权匹配（grant-matching）新增 6 次攻击成功，是最关键的一环；移除句柄归属、旧版初始化、目录过滤、头一致性各新增 2 次。移除审计不影响拦截（0），只影响证据。注意部分移除在主语料上为 0，但针对性见证用例仍会暴露问题，“0 变化”不代表机制无用。

## 4. 边界与局限（Table 3、5、8）

- 句柄/数据管道能阻止通过受控通道复制秘密，但**如果秘密以普通参数传递**（模型已经读到明文再写进参数），HCP 和 ACL 都会放行（“Ordinary parameter after internal read: Content written”）。
- 真实 MCP 服务实验（Table 8）：会话级“源预算”能阻止这类外泄，但也会误拒“读过敏感数据后发一条无关笔记”这样的合法操作；**标签缺失或标错时所有模式都会泄露**。

## 5. 原生任务与开销

- AgentDojo 24 个任务（Table 7）：DeepSeek 在直接执行下被诱导完成 4 个攻击目标；ACL 拦下 7/7、HCP 拦下 3/3 次攻击调用，攻击目标 0。代价是严格授权在 26 个会话中误拒了 40 次非攻击调用（多为日期、标题、频道名差异），GPT 无载荷时效用下降 8–13 个百分点。离线复核 241 次被拒写操作，219 次确实与参考动作存在实质差异。
- 开销（Table 9）：HCP 每次工作流增加约 0.26–0.31 ms，相对模型单次推理 4.6 s 可以忽略；ChainCaps 增加约 7–8 ms。

## 6. 展示建议

五种控制模式的“攻击成功 vs 合法完成”对比柱 + 移除检查的增量攻击柱（Table 4），适合在展示系统中说明“执行层护栏”的价值与边界。
