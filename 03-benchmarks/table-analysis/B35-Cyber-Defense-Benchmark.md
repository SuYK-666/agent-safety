# B35 Cyber Defense Benchmark — 数据表格与分析

> 表格：[analysis/tables](../B35-cyber-defense-benchmark/analysis/tables/)

## 1. 数据集结构

任务：给智能体一个装满 Windows 事件日志的数据库（505 列 schema），最多 50 次 SQL 查询，找出所有恶意事件的时间戳——即“威胁狩猎”。

论文全集（Table 2）：106 个 ATT&CK 攻击过程、77.4 万条原始日志、93 个子技术、12 个战术；由 Sigma 规则 + LLM 扩展标注出 23,268 个恶意事件 flag；组合成 26 个模拟攻击活动（每个 1,539–6,713 个 flag）。

**本包只有 1 个公开样例活动**（seed 176，完整集需向作者申请）。`data_sample_*.csv`：3 条攻击链共 18 步、3,912 个 flag，覆盖 9 个战术；flag 分布极不均匀，链 0 第 4 步一个步骤就有 2,763 个；87% 为核心事件（relevance=1）。日志解压后 356 MB。

- 覆盖分 = 每个“攻击过程×主机×用户”实例中被正确提交的叙事步骤比例。即使最好的 Opus 4.6 也有 45% 的攻击步骤未被发现；按原始 flag 算只找到约 4.5%。
- **没有任何模型通过**（要求 13 个战术召回都 ≥50%）：Opus 4.6 只过了 7 个。
- 智能体“看到了但没报”：Opus 4.6 平均在查询结果中见过 159 个 flag，只提交了 113 个。
- 作者仓库的 `cost.json` 中 Opus 4.7 成本为 $8.72，与论文表中 $3.66 不一致（`data_reference_cost.csv`），以论文为准并在系统中注明。

## 3. 按战术（Table 6，高危 flag 归一化召回）

规避防御、执行、持久化最容易发现（Opus 4.6 0.56–0.59，靠 PowerShell 编码、注册表 run key 等关键词即可）；**凭证访问、横向移动、收集、外泄**普遍最难（多数模型 <0.1，GPT-5 外泄 0.02、初始访问 0.02）。
